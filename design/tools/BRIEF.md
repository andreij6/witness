# Screen authoring brief (Witness design generator)

You are adding screens to a programmatic FigCraft design. Read these first:
- `design/tools/wlib.py`: tokens, `Doc`, components, layout and the `S[...]` names
- `design/tools/screens/*.py`: existing screens, which are the style reference
- `docs/SPEC.md` (product) and `docs/ARCHITECTURE.md` (technical truth)

Renders of the current screens are in `design/renders/*.png`. View a few before starting.

## Rules
1. **Edit only your own module** (`design/tools/screens/<module>.py`). Never edit `wlib.py`, `gen.py`, other modules or build scripts. If you need a helper, define it in your module.
2. **Create each new frame** with `f = screen(S["A1"])`, or `screen(S["X2"])` for desktop (1280×820). Phones are 412×915, the margin is `M = 16`, the nav bar sits at `NAV_Y = 835`, and the bottom action bar starts at `y = 834`.
3. **Chrome:**
   - App screens use `status_bar` / `app_bar` and either `nav_bar(f, "Home"|"Check")` (top-level tabs only) or `gesture(f)`.
   - Web screens use `browser(f, url, label)` and `web_footer(f, 812)`.
   - **Sheets and dialogs:** draw a simplified version of the screen underneath, then a full dim `D.rect(f, 0, 0, W, H, "#000000", a=0.45)`, then the sheet: `D.rect(..., SURF, radii=[26,26,0,0])` with a handle bar. Dialogs are centered cards with radius 24.
4. **Only use** icons that exist in `design/icons/icons.json` (`python3 -c "import json;print(sorted(json.load(open('design/icons/icons.json'))))"`) and the images in `IMAGES` (`crash bumper plate wide water rental hail rainbow moose random`). Don't fetch or generate new assets.
5. **Text:**
   - Short labels: `D.text(p, x, y, s, size, style, color)`.
   - **Wrapping or right/center alignment:** pass `w=` and `align="left"|"center"|"right"`.
   - Measure with `est_width(...)` and keep everything inside the 16 px margins. Nothing may overlap or clip. Wrap or shorten copy instead.
   - Styles: "Regular", "Medium", "Semi Bold", "Bold". Fonts: `SANS`, `MONO`.
6. **Color carries meaning:**

   | Color | Means |
   |---|---|
   | `OK` (green) | Proven only; use `OK_T` for green text on light backgrounds |
   | `EDIT` (teal) | *Matches an original, with changes* and declared edits |
   | `AI` (violet) | Generated by the on-device model only, via `generated_surface`, `generated_tag`, `ai_header` (with a flag) |
   | `CRIT` | Altered and destructive actions |
   | `WARN` / `WARN_T` | Queued or pending |
   | `MUTED` / `INK` | Neutral, *No record* |
   | `PRIMARY` | Actions and links |

   **Verdict copy:** "Original", "Matches an original" with the subline "with changes", "Altered", "No Witness record", and "Sealed · not yet anchored".
7. **Privacy:**
   - Public or web screens never show the phone model; say "Android phone" or "genuine Android phone".
   - Exact location is never public.
   - The domain is `DOMAIN` (`witness.app`); case links are `case.witness.app/v/…#k=…`.
8. **Wire the prototype** with `goto(node_id, S["…"])` for primary buttons and rows.
9. **No code comments.** That's the repository convention.
10. **Validate after every change** with `python3 -I design/tools/gen.py /tmp/witness-check-<module>.figcraft` (run from the `witness` folder). It must print `wrote …` without errors. **Don't run `build.sh`** during authoring: FigCraft is single-instance and the render phase owns it.
11. **Quality bar:** same polish as the existing screens. Realistic content from the demo story:
    - **Hailstorm post:** Denver area, Nov 18, 4:12 PM, the house number and plate blurred, `record_id` `H4IL-7QK…`.
    - **Fender bender case:** Oak St & 5th Ave, plates `8KTR214` and `7MNV562`, 4 items.
    - **Kitchen ceiling leak:** 6 items.
    - **Move-out:** 12 items.

    Layouts should be balanced, with no large empty bands and sensible vertical rhythm on 8 px multiples.
